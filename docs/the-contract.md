# The contract between the stack and the vault

The operational version of this document lives inside the vault, at `vault/20 Maps/Working with the teammate stack.md`, because the assistant needs to find it from inside the vault. This page is the reasoning behind it, for a person deciding whether to run both.

## The one-line rule

**The stack answers *who is speaking and how*. The vault answers *what is true and where it came from*.**

Nearly every question about which file a thing belongs in resolves against that sentence. A rule about tone is stack. A fact with a source is vault. A promise made in public is vault, because the ledger is the record. A rule about what the assistant may touch is stack, except for editorial commitments the owner has made on the record, which the vault keeps regardless.

## Precedence

When the two disagree, the stack wins on voice, style and working method; the vault wins on facts, evidence, what has already been said, and what has been promised. The table in the vault note spells this out question by question.

## Where they collide

There are three places the two systems will drift into duplicating each other, and each has a rule.

**Voice.** The vault holds an *observed* voice note, built from quoted evidence in the works. The stack's `02-voice.md` is *declared*: how the owner wants to sound. Do not copy one into the other. The stack file points at the vault note as its evidence, and when they disagree, that is a finding to record in the audit log, not an error to correct silently. Either the voice has drifted or the owner has decided to change it, and both are worth knowing.

**Context.** The stack's `04-context.md` is the file the assistant weights most for what to do today, and it is the one most likely to swell into a stale copy of the vault's ledgers. The rule: `04` holds pointers and deltas, never lists. Anything that changes weekly lives in the vault; `04` says what changed since the last audit and what it means.

**Rules.** The stack's `05-rules.md` and the vault's `CLAUDE.md` both hold standing instructions. The test for which file a rule belongs in: *would it still apply if the owner were writing about a completely different subject?* If yes, it is a stack rule. If it is only true of this body of work, it is a vault rule. If a rule ends up in both, delete the vault copy and leave a pointer, because the stack is the one read at the start of every session.

## The principle they share

The stack's `03-anti-style.md` names false certainty and false specificity, numbers without provenance and confidence without evidence, as an offence against the writing. The vault enforces the same rule one claim at a time, through the `evidence:` field and the *Outside the work* line in every zettel. That is the strongest argument for running both: the stack alone leaves the principle as an aspiration, and the vault alone is a filing system with no standard to file against.

## Loading order

1. The stack, whole, first. It is a few thousand words, and that is the cost of the assistant knowing who it is working with.
2. One pack from the vault, never the vault. Five to twelve notes chosen for the job.
3. An opener from `06-opening-move.md`.

## Where they meet on the calendar

Three cadences, each doing what the others cannot. The vault logs daily. It synthesises weekly — an hour, written cold from the week's notes, which is where the compounding happens. The stack audits quarterly.

They meet at the audit, where three questions belong on the stack's checklist: did the sourcing backlog shrink, did the promises ledger shrink, and did the vault reduce inboxes or become one. A fourth is worth adding once the weekly habit exists: how many weekly syntheses actually got written this quarter. It is the honest measure of whether the practice is running, and a quarter of zero says more than any count of notes.

## If you only want one

Run the vault. The stack is the smaller thing to add later and can be built in an afternoon from the vault's own voice note and the rules you find yourself repeating. A vault with no stack is a good archive that has to be re-introduced every session. A stack with no vault is a good introduction to someone with nothing to say.
